# Working on solar-seg

## Objective and evidence

Build scientifically useful **instance** segmentations for the Solar Filament Segmentation Challenge 2026. Optimize valid Panoptic Quality (PQ), morphology, and reproducibility. Never claim a top placement, completed run, score, or reproduction without its saved evidence. Read `docs/competition.md`, `docs/validation.md`, and `docs/experiments.md` before changing the pipeline.

## Access and data

- Use the Kaggle Python SDK / CLI and `gh`. The owner explicitly prefers CLI/API access over Chrome.
- Use only `MAGFiLO_1.0_Annotations_kaggle2026_train.json` for supervised filament labels. Never download the complete public MAGFiLO annotations or import checkpoints trained on them: they overlap the competition test set.
- External unlabeled GONG data is permitted for self-supervised training. Add provenance, dates, license, duplicate audit, and an ablation before using it. The current baseline uses none.
- The host's 2026-08-21 clarification allows auxiliary metadata already supplied with training data. Masks, mask-derived boundaries, distances, and skeletons are preferred initially. Inference receives only the supplied grayscale H-alpha JPEG.
- Do not commit images, private annotations, credentials, caches, or model binaries to Git history. Publish approved model artifacts separately with hashes and provenance. Keep data licensing separate from source licensing.

## Validation and submissions

- All annotations/crops/augmentations of a physical observation belong to one split. Current folds group 27-day time blocks and exact pixel duplicates. A three-day embargo separates optimization data from calibration/holdout.
- Freeze split hashes. Tune on calibration only. Inspect the locked holdout once for a frozen candidate, after selecting it on calibration. Do not repeatedly select candidates on holdout results; record any exposure and move to a fresh evaluation protocol if needed.
- Reproduce the organizer's **pooled per-annotator PQ**, strict IoU > 0.5. Dice and per-image mean PQ are diagnostics, not the ranking metric. Preserve separate annotators at evaluation.
- Predicted instances must be nonempty, unique, and pixel-disjoint. Encode compressed COCO counts in Fortran order at **2048 x 2048**. One CSV row per filament; preserve the image prefix exactly.
- Track zero-detection images in the coverage sidecar. Never insert dummy empty masks or copy test annotations.
- Respect five submissions/day and two final selections. The user has authorized legitimate competition submissions; do not ask again for routine gated submissions. Do not send forum messages or email without explicit authorization.
- Run `python -m pytest -q` and `ruff check solarseg scripts tests` for relevant code changes. Test evaluator parity against the downloaded official notebook locally.

## Code and documentation

- Python 3.12; pin utilized packages in `requirements.txt`. Keep commands copyable and defaults explicit.
- Maintain small reusable modules in `solarseg/`. `notebooks/canonical.ipynb` is the workflow entry point, generated by `scripts/build_notebook.py`. Do not let notebook and module implementations diverge.
- Every run records data/split/code/checkpoint hashes, configuration, seeds, hardware, runtime, calibration and holdout results, and submission status. Use new run directories rather than overwriting a completed checkpoint.
- Report planned work as planned. The current compact U-Net is a baseline, not a literature-winning method. Document failures and limitations.
- The subsequent-development CV index is `configs/nested-cv.json`; its generator and leakage tests are separate from the original split. Read `docs/next-campaign.md`. Preserve the original submitted candidate and never attach its holdout result to a new checkpoint.
- Keep source public by the competition deadline and through winner announcement. Public competition code must also be available through an associated Kaggle notebook/forum; prefer the notebook.
- The final package needs the specified four-page PDF, accessible repository, pinned requirements, canonical notebook, checkpoints/instructions, and the final Google form. The participant must understand and explain every major component, including AI-assisted work.
